# 可编辑性验证材料

本文件说明「怎么证明输出的 PPTX 不是整页截图」，以及在 3 套素材上的实测数据。

## 一、结论先行

| 检验项 | 测试1 | 测试2 | 测试3 |
|---|---|---|---|
| 幻灯片页数 | 10 | 10 | 10 |
| 文本对象（文本框） | 202 | 162 | 126 |
| 图片对象 | 107 | 71 | 34 |
| 原生表格 | 1 | 0 | 0 |
| 可编辑字符总数 | 3125 | 2503 | 1591 |
| 整页截图数量 | 0（只有 4 页含「去字背景图」） | 0（2 页含背景图） | 0（1 页含背景图） |
| 平均结构相似度 SSIM | 0.9443 | 0.9341 | 0.9604 |

> 「整页截图」判定：每页都至少包含可编辑文本框；带背景图的页，其背景图是**文字已擦除**的底图，文字对象叠在它上面，并非把原图直接铺满。

## 二、三种验证方式

### 方式 1：结构清单（最直接，无需人工）

```bash
python verify.py samples/测试1.pdf output/测试1.pptx output/verify/测试1
```

脚本用 `python-pptx` 遍历每页每个 shape，按类型统计并写入 `verify.json`：

```json
"inventory": [
  {"page": 1, "textbox": 8, "picture": 0, "table": 0, "shape": 1, "chars": 176},
  ...
]
```

只要 `textbox > 0` 且 `picture` 不是「1 张整页图」，即可判定该页具备可编辑结构。

### 方式 2：渲染回图像 + SSIM（证明视觉没崩）

同一脚本会用 WPS（Windows）或 LibreOffice（Linux）把 PPTX 渲染成 PDF，再逐页与原 PDF 做 SSIM：

- 输出目录里每页一张 `compare_XX.jpg`：**左边原图，右边转换结果**，可直接肉眼核对；
- `verify.json` 里记录每页 `ssim`。

### 方式 3：人工交互验证（评审时用）

1. 用 PowerPoint / WPS 打开 `output/测试1.pptx`；
2. 单击标题（如第 5 页「案例合集 · 多图网格」）→ 出现文本框选中框与光标，可直接改字、改字号、改颜色；
3. 单击照片 → 出现图片选中框与八个缩放手柄，可单独拖动/缩放/裁切；
4. 打开「开始 → 选择窗格」，可看到每页的 `bg_XX / img_XX_XX / txt_XX / table_XX` 对象命名，对象之间彼此独立；
5. 第 8 页表格：双击单元格即可编辑，右键可插入/删除行列。

## 四、验证产物位置

```
output/
├── 测试1.pptx / 测试2.pptx / 测试3.pptx        # 交付件
├── 测试1.pptx.report.json …                    # 每页对象数量报告

```

## 五、复现步骤（约 2 分钟）

```bash
pip install -r requirements.txt
python cli.py samples -o output                 # 重新生成 3 个 pptx
python verify.py samples/测试1.pdf output/测试1.pptx output/verify/测试1
```

> Windows 下渲染验证需要本机安装 WPS（脚本调用 `KWPP.Application` 导出 PDF）；Linux 下自动回退 LibreOffice（`soffice`）。转换本身不依赖这两个软件。
